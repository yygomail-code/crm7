# Дизайн-ревью интерфейса (скриншоты + промпт для vision-агента)

Скрипт `frontend/tools/design-review/capture.mjs` снимает все основные экраны CRM
(desktop 1440×900 и mobile 390×844, роли manager/client/admin) и складывает их в
`frontend/artifacts/design-review/run-<дата>/` вместе с `manifest.json` и галереей
`index.html`. Каталог `frontend/artifacts/` в `.gitignore`.

## Запуск

Нужны запущенные фронтенд (`npm run dev`) и API, а также установленный Edge (или Chrome).

```powershell
cd frontend
# пароли — из файла, чтобы не светить их в командной строке
$env:CRM_PASSWORD_FILE = "$env:TEMP\opencode\seed_passwords.json"
npm run screenshots
```

Файл паролей — JSON вида `{"manager": "...", "client": "...", "admin": "..."}`.

Полезные переменные окружения:

| Переменная | Значение |
| --- | --- |
| `CRM_BASE_URL` | фронтенд, по умолчанию `http://localhost:5173` |
| `CRM_API_URL` | API v2, по умолчанию `http://127.0.0.1:8080/api/v2` |
| `CRM_PASSWORD_FILE` | JSON-файл с паролями по логинам (рекомендуется) |
| `CRM_PASSWORD` / `CRM_PASSWORD_<ROLE>` | общий пароль / пароль конкретной роли |
| `CRM_ROLES` | `manager,client,admin` (по умолчанию все) |
| `CRM_VIEWPORTS` | `desktop,mobile` (по умолчанию оба) |
| `CRM_BROWSER_CHANNEL` | `msedge` (по умолчанию) или `chrome` |
| `CRM_SETTLE_MS` | пауза после загрузки страницы, по умолчанию 1600 мс |
| `CRM_CAPTURE` | `viewport` \| `full` \| `both` (по умолчанию `both`) |

Важно: full-page снимки дают артефакты с `position: fixed` элементами (cookie-баннер и нижнее
меню выглядят «обрезанными» и «наложенными»). Для дизайн-ревью используйте viewport-снимки
(`CRM_CAPTURE=viewport`) или оба варианта; проверено, что в реальном viewport эти элементы
корректны.

Что снимается: manager — 13 экранов (заявки, карточка заявки, клиенты, карточка
клиента, чат, склады, отчёты, замещения, уведомления, профиль, «о системе»,
юридический документ); client — 10 экранов; admin — 14 экранов (включая вкладки
админки: пользователи, аудит, роли, справочники, документы; настройки).

## Как использовать с vision-агентом

1. Открыть `frontend/artifacts/design-review/run-.../index.html` — быстрый просмотр.
2. Отдать агенту скриншоты одной роли и одного вьюпорта за проход (не всё сразу):
   для сравнения и поиска неконсистентности — по 5–8 снимков за сообщение.
3. Использовать промпт ниже; для повторных проходов добавлять «учитывай предыдущие
   замечания, не повторяй их, ищи новые».

### Промпт (полная версия)

```text
Ты — senior product designer и UX-исследователь. Оцениваешь интерфейс корпоративной
CRM для продажи смартфонов (CRM7).

Контекст продукта:
- Менеджеры работают за десктопом с большим объёмом данных: заявки, клиенты, склады, отчёты.
- Клиенты — mobile-first: оформить заявку, посмотреть остатки, написать в чат.
- Дизайн-система: светлая тема, скруглённые карточки, синий акцент (primary),
  серые границы, компактные таблицы, шрифт system-ui.
- Скриншоты: desktop 1440×900 и mobile 390×844, роли manager / client / admin.

Проверь по чек-листу:
1. Визуальная иерархия и сканируемость: понятно ли за 3 секунды, где заголовок,
   главное действие и данные.
2. Консистентность: одинаковые паттерны для одинаковых задач (кнопки, таблицы,
   карточки, пустые состояния) внутри и между экранами.
3. Сетка, отступы, выравнивание: ритм, поля, «прилипание» элементов, выравнивание
   чисел по правому краю, заголовков — по левому.
4. Типографика: размеры/веса заголовков, длина строк, переносы длинных названий
   (позиции, ФИО, склады).
5. Цвет и контраст: контраст текста ≥ 4.5:1 (WCAG AA), различимость состояний
   (просрочено, закрыто, приоритет), не полагаться только на цвет.
6. Состояния: пустые, загрузка, ошибка, «нет прав», очень длинные значения.
7. Формы: заметность главного действия, порядок кнопок, подписи полей, подсказки,
   блокировка при выключенных продажах.
8. Данные: плотность таблиц, читаемость чисел, сортировка/фильтры, пагинация.
9. Мобильный опыт: тап-зоны ≥ 44px, горизонтальные скроллы, переносы, скрытые
   второстепенные колонки.
10. Доступность: видимый фокус, подписи кнопок-иконок, контраст, размер шрифта ≥ 13px.
11. Тексты: понятность, единый тон, отсутствие жаргона и англицизмов без нужды.
12. Эвристики Нильсена (кратко по каждому экрану: видимость состояния системы,
    соответствие реальному миру, контроль и свобода, предотвращение ошибок,
    узнавание вместо припоминания, гибкость, эстетичный минимализм, диагностика
    ошибок, помощь, документация).

Формат ответа:
Таблица: | # | Экран | Элемент | Проблема | Принцип (эвристика) | Рекомендация | Приоритет |
Приоритеты: critical (мешает задаче), important (замедляет/путает), minor (косметика).
После таблицы: топ-5 изменений с максимальным эффектом и список того, что сделано
хорошо (чтобы не сломать при правках).

Правила:
- Оценивай только то, что видно на скриншотах; не выдумывай элементы и состояния.
- Не предлагай перерисовку с нуля и новый брендинг — только точечные улучшения
  в рамках текущей дизайн-системы.
- Каждое замечание — конкретно: где (экран, элемент), что не так, почему, как исправить.
- Если для вывода не хватает данных — напиши «нужен скриншот состояния X».
- Не давай советов по коду и технологиям — только дизайн и UX.
```

### Промпт (короткая версия, для одной страницы)

```text
Ты — senior UX-дизайнер. Оцени экран корпоративной CRM (скриншот приложен).
Контекст: <роль пользователя, desktop/mobile, задача экрана>.
Найди до 10 проблем по приоритету (critical/important/minor): иерархия, отступы,
консистентность, контраст, состояния, тексты, мобильные тап-зоны. Формат: таблица
«Элемент | Проблема | Рекомендация | Приоритет» + топ-3 исправления. Оценивай только
видимое, без перерисовки с нуля, без советов по коду.
```

## Другие инструменты (дополнение к vision-агенту)

- **axe-core / @axe-core/playwright** — автоматическая проверка доступности в CI.
- **Lighthouse CI** — производительность, контраст, best practices.
- **Pa11y CI** — регрессии доступности.
- **Playwright visual regression** — пиксельные диффы скриншотов между сборками.
- **Attention Insight** (внешний сервис) — AI-тепловые карты внимания; только на
  демо- или обезличенных скриншотах.

## Безопасность

Скриншоты содержат данные стенда. Не отправлять снимки с реальными клиентскими
данными во внешние сервисы: использовать демо-данные (`api/bin/seed-demo.php`) или
корпоративный контур для vision-модели. `frontend/artifacts/` не коммитится.

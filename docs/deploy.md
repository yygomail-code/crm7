# Развёртывание CRM7

Один хостинг может обслуживать несколько проектов CRM7 в разных категориях:
лендинг в корне, прод и демо — в подкаталогах. Каждый проект — самостоятельная
копия (сборка фронтенда + каталог `api/` + `storage/`) со своим конфигом и своей
базой данных. Сборка фронтенда не привязана к корню: пути относительные, адрес
API по умолчанию — `./api/v2` (внутри своей категории).

## Структура каталогов

```
/public_html/                 ← корень сайта (лендинг и т.п.)
  demo/                       ← категория «демо»
    index.html, assets/…      ← сборка фронтенда (frontend/dist)
    config.js                 ← window.CRM_CONFIG (адрес API, название приложения)
    api/                      ← копия каталога api/
      public/                 ← точка входа (index.php, router.php, .htaccess)
      src/, db/, bin/         ← код, миграции, cron
      config/.env             ← настройки проекта (база, базовый путь, почта)
      storage/, var/          ← файлы и логи (вне webroot)
  prod/
    … то же для прод-проекта
```

## Подготовка нового проекта

1. Скопировать `frontend/dist` в каталог категории (например `demo/`).
2. Скопировать каталог `api/` в `demo/api/`.
3. В `demo/api/config/.env` задать:
   - `API_BASE_PATH=/demo/api/v2` — префикс пути API (локально — `/api/v2`);
   - `DB_HOST`, `DB_PORT`, `DB_NAME=<своя база>`, `DB_USER`, `DB_PASS`;
   - `APP_URL=https://сайт/demo`, `CORS_ORIGIN` — если фронтенд на другом домене.
4. Создать базу и применить миграции:
   ```sql
   CREATE DATABASE crm_demo CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   GRANT ALL PRIVILEGES ON crm_demo.* TO 'crm_app'@'localhost';
   ```
   ```
   php demo/api/bin/migrate.php
   php demo/api/bin/seed-dev.php --password=…     # только для демо/тестового проекта
   ```
5. Cron: `php demo/api/bin/cron.php` (рассылки отчётов, SLA, передачи клиентов).

Переписывание URL для фронтенда не нужно — используется hash-роутинг.
Для API на Apache положить в `demo/api/.htaccess`:

```apache
RewriteEngine On
RewriteRule ^ public/index.php [L]
```

На nginx:

```nginx
location /demo/api/ {
    try_files $uri /demo/api/public/index.php?$query_string;
}
```

## Адрес API без пересборки

`demo/config.js` (рядом с `index.html`) задаёт адрес API на этапе запуска:

```js
window.CRM_CONFIG = { apiV2Base: './api/v2' };
```

Если API размещён в другом месте (например, общий для нескольких фронтендов) —
достаточно поправить `config.js`, пересборка не требуется. Переменные
`VITE_API_V2_BASE` / `VITE_API_BASE` при сборке и `window.CRM_CONFIG` работают
как переопределения; по умолчанию — относительный `./api/v2`.

## База данных из интерфейса администратора

Настройки → «База данных» (уровень 50+): сервер, порт, база, пользователь,
пароль (пустое поле — «не менять»). Кнопка «Проверить подключение» проверяет
соединение, «Сохранить» — проверяет и записывает `demo/api/config/database.json`
(предыдущий файл — `database.json.bak`). Приоритет: `database.json` → `.env` и
переменные окружения. После смены базы войдите заново — сессии хранятся в базе.

## Несколько проектов в одной СУБД

Каждый проект использует отдельную базу на общем сервере MySQL/MariaDB —
штатный способ изоляции: свои таблицы, пользователь и бэкапы, никаких правок
SQL. База выбирается в `config/.env` или в интерфейсе администратора.
Общая база с префиксом таблиц потребовала бы переписать все запросы и не даёт
выигрыша на обычном хостинге.

## Проверка после развёртывания

- `https://сайт/demo/` открывается, статика и `config.js` отдаются (200);
- вход в систему и список заявок работают — значит, путь API и база верны;
- в Настройках → «База данных» источник и параметры соответствуют ожидаемым;
- `https://сайт/demo/api/v2/health` (или любой публичный маршрут) отвечает;
- cron выполняется по расписанию.

## Восстановление доступа

- **Забыт/сменён пароль администратора.** Пересоздать стандартные учётные записи
  (если их нет): `php demo/api/bin/seed-dev.php --password=<новый пароль>`.
  Существующие логины не трогаются, отсутствующие создаются заново.
- **Смена базы данных «в никуда».** Переключение в админке разрешено только для
  базы с таблицами CRM и активным администратором; если доступ всё же потерян —
  удалить `demo/api/config/database.json` (или вернуть `database.json.bak`),
  настройки снова возьмутся из `.env`.
- **Потерян последний администратор.** API не даёт заблокировать или понизить
  последнего активного администратора (50+), нельзя заблокировать себя и сменить
  свою роль; администратор (50) не может управлять сисадмином (90). Если учётные
  записи повреждены вручную в базе — восстановить через `seed-dev.php`.
